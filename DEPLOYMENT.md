# MUT-3 Connector — Static Landing Page & Robokassa Checkout

Статичный коммерческий сайт-лендинг для программного продукта **MUT-3 Connector**, оптимизированный для публикации на **GitHub Pages**, приёма платежей через **Robokassa** от российских и зарубежных физических лиц и прохождения повторной модерации платёжного сервиса.

---

## 1. Назначение и архитектура

Сайт полностью статический (HTML5, CSS3, ES-модули JavaScript) и не требует сервера или базы данных.

- **Стилистика:** Windows 11 Fluent 2 (полное визуальное соответствие десктопному приложению MUT-3 Connector).
- **Локализация:**
  - Английский по умолчанию (`en`).
  - Определение языка по локали браузера пользователя (пользователи из РФ и СНГ автоматически получают русскую версию).
  - Ручной переключатель языка `[ EN | RU ]` в шапке с сохранением выбора в `localStorage`.
- **Юридические разделы:** Отдельные полнотекстовые страницы на английском и русском языках (`/terms/`, `/ru/terms/`, `/privacy/`, `/ru/privacy/`, `/refund/`, `/ru/refund/`).
- **Безопасность:** Никаких секретов Robokassa (Password #1 / #2, private API keys) в коде фронтенда. Все CTA ведут на защищённый hosted checkout Robokassa.

## 3. Локальный запуск и просмотр

Так как проект использует нативные ES-модули (`<script type="module">`), открывать `index.html` рекомендуется через локальный веб-сервер, а не по протоколу `file://`:

### Вариант 1 — Через Python (уже установлен в системе):
```powershell
cd c:\projects\mut-3-connector\landing
python -m http.server 8000
```
Затем откройте в браузере: `http://localhost:8000`

### Вариант 2 — Через VS Code Live Server / npx serve:
```powershell
npx serve c:\projects\mut-3-connector\landing
```

## 4. Как настроить перед публикацией

Все ключевые параметры вынесены в один файл:
👉 `landing/assets/js/config.js`

### 4.1. Изменение платёжной ссылки Robokassa
Откройте `landing/assets/js/config.js` и замените значение `robokassaUrl`:
```javascript
payment: {
  robokassaUrl: "https://auth.robokassa.ru/Merchant/Index.aspx?MerchantLogin=YOUR_LOGIN&OutSum=15&InvId=0&Desc=MUT-3+Connector+License&Culture=en",
}
```
*Все кнопки «Купить лицензию» на сайте автоматически обновят ссылку.*

### 4.2. Изменение цены
В `landing/assets/js/config.js` отредактируйте:
```javascript
product: {
  priceUsd: 15,
  priceEurDisplay: 14,
  ...
}
```

### 4.3. Обновление реквизитов продавца
В `landing/assets/js/config.js`:
```javascript
seller: {
  nameEn: "Artem Roshko",
  nameRu: "Рошко Артём",
  inn: "667000000000",       // Укажите ваш реальный ИНН
  cityEn: "Yekaterinburg, Russian Federation",
  cityRu: "г. Екатеринбург, Российская Федерация",
  email: "alfaslash@gmail.com",
  phone: "+7 (900) 000-00-00", // Укажите ваш реальный телефон
  telegram: "@mut3connector_support",
}
```
*Также при необходимости проверьте и синхронизируйте эти реквизиты в юридических документах (`terms/`, `ru/terms/`).*

### 4.4. Замена или добавление скриншотов
Файлы скриншотов находятся в `landing/assets/img/`:
- `screenshot-manage.jpg` — скриншот вкладки управления;
- `screenshot-backup.jpg` — скриншот бекапа;
- `app_icon.png` — иконка программы.

Вы можете просто заменить эти файлы на новые с теми же именами либо обновить пути в `index.html`.

## 5. Публикация на GitHub Pages

### Способ 1: Отдельная ветка `gh-pages`
1. Создайте ветку `gh-pages`:
   ```powershell
   git checkout -b gh-pages
   ```
2. Разместите содержимое папки `landing` в корне ветки `gh-pages` и запушьте в GitHub:
   ```powershell
   git push origin gh-pages
   ```
3. В настройках репозитория на GitHub перейдите в **Settings → Pages** и в качестве источника выберите ветку `gh-pages` (папка `/ (root)`).

### Способ 2: Публикация из папки `docs` ветки `main`
Если вы хотите публиковать из ветки `main`:
1. Скопируйте файлы из `landing` в папку `docs` в корне репозитория.
2. В **Settings → Pages** выберите ветку `main` и папку `/docs`.

## 6. Настройка собственного домена (Custom Domain) и HTTPS

1. В файле `landing/CNAME` укажите ваш домен (например, `mut3connector.com`).
2. В панели управления DNS вашего регистратора добавьте записи:
   - Для apex-домена (`mut3connector.com`) — A-записи на IP-адреса GitHub Pages:
     ```text
     185.199.108.153
     185.199.109.153
     185.199.110.153
     185.199.111.153
     ```
   - Для поддомена `www` — CNAME-запись на `<ваш-аккаунт>.github.io`.
3. В настройках GitHub Pages (**Settings → Pages**):
   - Укажите **Custom domain**: `mut3connector.com`.
   - Обязательно включите галочку **Enforce HTTPS** (сертификат Let's Encrypt выпустится автоматически в течение нескольких минут).

## 7. Чек-лист перед отправкой на модерацию в Robokassa

Перед повторной отправкой магазина на активацию в Robokassa убедитесь:

- [ ] **Домен и HTTPS:** сайт открывается по HTTPS без предупреждений безопасности браузера.
- [ ] **Главная страница:** открывается на английском языке по умолчанию; при наличии русской локали в браузере корректно работает автопереключение или ручной переключатель `[ EN | RU ]`.
- [ ] **Реквизиты продавца:** в футере и карточке продавца указаны реальные ФИО самозанятого, ИНН, город, действующий email и телефон.
- [ ] **Понятный товар:** явно описано, что продаётся персональная лицензия на ПО для конфигурирования J2534-адаптеров с MUT-III SE.
- [ ] **Цена:** на видном месте указана стоимость ($15 USD, ориентировочно 14 €), без расплывчатых формулировок «по запросу».
- [ ] **Способ оплаты:** нейтральное пояснение, что оплата принимается картами через Robokassa для поддерживаемых стран.
- [ ] **Электронная доставка:** чётко указано, что товар цифровой, доставка на email по коду HWID в течение 12–24 часов.
- [ ] **Совместимость:** перечислены поддерживаемые адаптеры (Сканматик 2 ПРО, Dialink, OpenPort 2.0 и др.) и указаны ограничения (требуется 32-bit DLL, клоны не гарантируются).
- [ ] **Юридические страницы:** опубликованы и доступны по ссылкам:
  - [x] Terms of Sale / Public Offer (`/terms/` и `/ru/terms/`)
  - [x] Privacy Policy (`/privacy/` и `/ru/privacy/`)
  - [x] Refund Policy (`/refund/` и `/ru/refund/`)
- [ ] **Страницы возврата платежа:** созданы страницы `/payment-success/` и `/payment-failed/` (с нейтральной формулировкой «Если ваш платёж был успешно завершён...»).
- [ ] **Платёжная ссылка:** в `config.js` подставлена рабочая ссылка магазина Robokassa.
- [ ] **Безопасность:** в клиентском коде отсутствуют пароли и секреты Robokassa (Password #1 / #2).

## 8. Предупреждение о безопасности (Robokassa Secrets)

> [!WARNING]
> Никогда и ни при каких обстоятельствах не размещайте в репозитории или в коде сайта:
> - Пароль №1 (Password #1);
> - Пароль №2 (Password #2);
> - Приватные API-ключи Robokassa;
> - Скрипты генерации цифровой подписи CRC / MD5 / SHA-256 на клиенте.
>
> Первая версия проекта работает исключительно через защищённую платёжную ссылку (hosted checkout), где сумма и параметры заказа формируются безопасно.
